OutfitDB

OutfitDB v0.2.0

OutfitDB 示範了任何人都能為沒有標準數學解的日常問題，建立個人資料庫並訓練自己的 ML 模型。 三段簡短的評分流程教會它你對溫度的感受、你的美感與你對場合的判斷 — 推薦結果甚至會從你自己的衣櫥裡找出你從沒想過的搭配。 本機優先（local-first）：你的資料永遠不會離開你的電腦。

線上展示

完整的 FastAPI 後端部署在 Render 免費方案上，並預先載入 Tester 衣櫥（54 件衣物、17 MB 照片）。每一次互動都會打到真正的 Python 服務：SQLAlchemy 操作 SQLite、XGBoost 為穿搭排序、Jinja 渲染樣板，lifespan hook 在每次冷啟動時把內建的種子資料複製到 /tmp。推薦流程、個人檔案切換、訓練頁面、行事曆、情境建構器，以及洗衣／髒污／穿著狀態機全部端對端運作 — 這不是靜態的模擬畫面。

Render 免費方案會在閒置 15 分鐘後讓執行個體休眠，因此第一次造訪可能需要約 50 秒等待容器喚醒，之後的載入則是即時的。如果 iframe 沒有回應，請直接開啟 展示網址 — 喚醒時間是一樣的。 每次冷啟動都會清空 /tmp 並從內建快照重新載入 Tester，所以展示環境永遠會回到乾淨的狀態。

它做什麼

你只需上傳一次衣服的照片。應用程式從你的評分中學習三個彼此獨立的偏好軸，並在推薦時將它們串接起來，因此只要有一個硬性條件不過（溫度不對、場合不對），不論穿搭再好看，分數都會歸零。

第一階段
溫度
六個溫區（嚴寒 / 寒冷 / 涼爽 / 溫和 / 溫暖 / 炎熱）。多標籤分類器——一套穿搭可適用多個溫區。
×
第二階段
美感
純粹的外觀評分：顏色、剪裁、層次。使用者以四分制評分，不考慮溫度與場合。
×
第三階段
場合
從 gym 到 formal_event 共九種活動類型。多標籤設計，一套穿搭可適用多種活動。

推薦分數將三個訊號與兩個軟性因子（新鮮度、恢復度）相乘，讓模型既能把被冷落的衣物帶出來，也尊重各軸的純粹判斷。

為什麼採用本機優先

這個應用程式蒐集的資料 — 你穿什麼、不穿什麼、把什麼評為「喜歡」或「討厭」— 極度私人。把這些資料放在共用伺服器上會帶來一連串義務（身分驗證、靜態加密、GDPR 式的資料處理），徒增風險，卻沒有給使用者任何他們真正需要的東西。

OutfitDB 以桌面應用程式的形式發佈。每位使用者的資料都存放在作業系統標準的應用程式資料目錄中（macOS 為 ~/Library/Application Support/OutfitDB/profiles/{name}/，Windows 為 %APPDATA%/OutfitDB/profiles/{name}/），包含單一 SQLite 檔案與一個圖片資料夾。應用程式啟動只綁定 127.0.0.1 的 uvicorn，開啟系統瀏覽器，完全在使用者的電腦上執行。除了選用的天氣與地理編碼查詢之外（兩者都是由使用者的瀏覽器直接呼叫公開 API，不經過我架設的任何伺服器），沒有任何資料經過網路。

六個實作階段

第一階段 — 層次覆蓋模型

熱覆蓋公式 T_cover = T_BASE − α·coverage 搭配雙曲線（舒適 + 美感），決定任何溫度下的最佳疊穿層數，取代手寫的天氣規則。

第二階段 — XGBoost 偏好模型

每位使用者各自一個二元分類器，輸入為 100 維特徵向量。冷啟動時退回使用衣物平均評分；累積 10 筆以上評分後切換為訓練好的模型。

第三階段 — 本機優先儲存

每個個人檔案一個 SQLite 綱要，搭配冪等的 ALTER TABLE 遷移。個人檔案資料夾位於應用程式套件之外，因此更新應用程式不會影響資料。

第四階段 — 多階段訓練

純軸標註：三個獨立的分類器分別在互不重疊的評分表上訓練。推論時將三個機率相乘，任何一軸不及格就會讓分數歸零。

第五階段 — 探索體驗打磨

混紡成分（例如 40/60 棉／亞麻以加權 multi-hot 表示）、四狀態生命週期（clean / worn / in_laundry / unavailable）、新衣物優先訓練、針對特殊穿搭的強制推薦覆寫。

第六階段 — 桌面應用程式打包

PyInstaller .spec 處理 FastAPI 技術堆疊在凍結模式下的各種陷阱（Jinja2 路徑、PIL 外掛、xgboost 原生函式庫）。手動對照公開 release 清單檢查更新。macOS DMG 採拖曳至 Applications 的安裝版面。

macOS

  1. 點選上方的下載 Mac 版，會取得 OutfitDB-0.2.0.dmg。
  2. 雙擊 DMG。視窗中會顯示 OutfitDB.app 與 Applications 資料夾捷徑。
  3. 將 OutfitDB.app 拖曳到 Applications，安裝完成。
  4. 透過 Spotlight（&#8984; Space → 輸入「OutfitDB」）、Launchpad 或 Finder → Applications 啟動。
僅限第一次啟動： macOS Gatekeeper 會以「無法驗證開發者」為由封鎖未簽署的應用程式。請在應用程式上按右鍵 → 開啟 → 確認。之後的啟動即可正常運作。應用程式完成程式碼簽署後，這個步驟就不再需要。

第一次啟動時，應用程式會自動建立一個 Tester 個人檔案，內含 54 件範例衣物（與上方線上展示相同的衣櫥），讓你不必先上傳自己的衣服就能立刻體驗推薦流程。你隨時可以從右上角的使用者切換器新增自己的個人檔案；刪除 Tester 後，下次啟動不會再自動建立（種子資料只會在個人檔案資料夾為空時載入）。應用程式會在你的預設瀏覽器中開啟 http://127.0.0.1:18888。

Windows

從 v0.2.0 release 取得 OutfitDB-0.2.0-windows.zip（或使用本頁最上方的下載 Windows 版按鈕）。解壓縮到任意位置 — 例如 C:\Users\<you>\Apps\OutfitDB\ — 然後雙擊 OutfitDB.exe。應用程式會在 http://127.0.0.1:18888 啟動本機網頁伺服器，並在你的預設瀏覽器中開啟。

僅限第一次啟動： Windows SmartScreen 會以「Microsoft Defender SmartScreen 已防止某個無法辨識的應用程式啟動」為由封鎖未簽署的應用程式。請點選其他資訊 → 仍要執行。之後的啟動即可正常運作。執行檔完成程式碼簽署後，這個步驟就不再需要。

Windows 版由 GitHub Actions 工作流程（build-windows.yml）產生：每當原始碼儲存庫推送 v* 標籤時，就在 windows-latest runner 上執行 pyinstaller outfitdb.spec。衣櫥種子資料的流程與 macOS 相同 — 第一次啟動會自動建立內建的 Tester 個人檔案。

如果你想自行從原始碼建置：

# Windows + Python 3.11 / 3.12
git clone https://github.com/chentzuyuan/OutfitDB.git
cd OutfitDB
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install pyinstaller
pyinstaller outfitdb.spec --noconfirm
# Output: dist\OutfitDB\OutfitDB.exe
